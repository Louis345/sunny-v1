## Proof 1 — Do child signals materially shape Quest and Boss?

### Question

Given the same mathematics and academic performance, do different factual engagement histories produce meaningfully different experiences without changing the learning target?

### Synthetic branches

Create three JSON event histories from the same frozen baseline cycle:

1. **Visual construction evidence**
   - High rating after a construction/manipulation activity.
   - Completed and replayed.
   - Low assistance and low invalid-action count.

2. **Fast challenge evidence**
   - High rating after a paced challenge.
   - Completed without replay.
   - Short time to first valid action.

3. **Negative or uncertain evidence**
   - Low rating or Skip.
   - Abandonment, confusion, or assistance recorded separately.
   - No inferred preference conclusion.

### Checklist

- [x] Hold the academic contract, items, correctness, assistance, and difficulty constant.
- [x] Feed each factual history into the same production progression Planner.
- [x] Save the exact evidence IDs the Planner and Creator received.
- [x] Generate one Quest and, after qualifying Quest evidence, one Boss per branch.
- [x] Verify each experience remains unseen transfer or synthesis rather than copied practice.
- [x] Compare opening action, interaction, stakes, recovery, progression, payoff, and visual direction.
- [x] Confirm differences are experiential—not merely color, title, or theme changes.
- [x] Confirm weak academic evidence cannot reach Boss regardless of a high rating.
- [x] Confirm a low rating can influence presentation while correct academic evidence remains intact.

### Pass

- Quest/Boss visibly respond to supported engagement evidence while preserving identical academic truth.
- The report can point from each design difference to specific factual evidence IDs.
- Ratings influence creative hypotheses but never mastery or automatic preference conclusions.

### Fail

- All branches produce essentially identical experiences.
- Personalization is only cosmetic.
- A high rating overrides weak learning evidence.
- The system invents a preference from one observation.
- Quest or Boss is a static question card rather than an immersive playable experience.

## Proof 3 — Can reality overturn Sunny's mastery belief?

### Question

If Sunny predicts readiness from strong in-app performance but returned independent work contradicts it, does Sunny admit the prediction was wrong and continue teaching?

### Required branches

1. **Strong in-app, strong returned work**
2. **Strong in-app, weak returned work**
3. **Strong in-app, assisted returned work**
4. **Weak in-app, high fun rating**

### Checklist

- [ ] Strong Boss performance produces only `predicted_ready` and `awaiting_calibration`.
- [ ] The parent report uses “Sunny predicts,” not “mastered,” before external evidence.
- [ ] `ready_independent` requires confirmed, correct, explicitly unassisted returned work.
- [ ] Every readiness claim cites canonical observations and real prediction evaluations.
- [ ] Contradictory returned work rejects or revises the original assumption.
- [ ] Contradiction changes readiness to `not_yet_ready`, `ready_with_support`, or `insufficient_evidence` as justified.
- [ ] Sunny creates targeted Support or requests more independent evidence under the same homework ID.
- [ ] A new immutable prediction is written for the support chapter.
- [ ] Assisted success never becomes independent readiness.
- [ ] Fun ratings, completion, Elli help, and replay never become mastery evidence.
- [ ] A later successful independent return can update readiness without deleting the earlier mistake.

### Pass

- Sunny is accountable to reality: it records that its prediction was wrong, explains why, changes the next intervention, and preserves the full audit trail.
- A parent can see: believed → predicted → happened → assessment → next action.

### Fail

- Boss completion is called mastery.
- Returned work cannot overturn the in-app conclusion.
- Weak or assisted work closes the cycle.
- Sunny silently rewrites the original assumption instead of assessing it.
- A support session begins a disconnected board/history.
